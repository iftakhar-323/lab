## Concept

| Term | Definition |
|---|---|
| EXPLAIN | A PostgreSQL command that shows the execution plan of a query, revealing how tables are scanned. |
| Distributed Query Plan | The execution strategy generated by the Citus coordinator, indicating which parts of the query run on worker nodes. |
| Scatter-Gather | A query pattern where the coordinator sends a query to all workers and aggregates the results locally. |

When you run `EXPLAIN` on a Citus coordinator, you'll see a `Custom Scan (Citus Adaptive)` node. If a query filters by a specific `tenant_id`, the plan targets exactly one worker shard, yielding high performance. If the filter is missing (e.g., counting all orders globally), the coordinator must scatter the query to all shards and gather the results, which is resource-intensive.

## Step 2: Define and Deploy the AWS Infrastructure

Replace the contents of `citus-benchmark-lab/infra/__main__.py` with the following Pulumi code to provision a Citus cluster via Docker Compose on a single EC2 instance:

```python
import pulumi
import pulumi_aws as aws

user_data = """#!/bin/bash
apt-get update -y
apt-get install -y docker.io docker-compose
systemctl start docker
systemctl enable docker
usermod -aG docker ubuntu

cat > /home/ubuntu/docker-compose.yml << 'EOF'
version: '3.8'
services:
  coordinator:
    image: citusdata/citus:12.1
    ports:
      - "5432:5432"
    environment:
      - POSTGRES_PASSWORD=citus_password
      - POSTGRES_USER=citus
      - POSTGRES_DB=citus
    command: ["-c", "listen_addresses=*"]
  worker1:
    image: citusdata/citus:12.1
    environment:
      - POSTGRES_PASSWORD=citus_password
      - POSTGRES_USER=citus
      - POSTGRES_DB=citus
  worker2:
    image: citusdata/citus:12.1
    environment:
      - POSTGRES_PASSWORD=citus_password
      - POSTGRES_USER=citus
      - POSTGRES_DB=citus
EOF

cd /home/ubuntu/
docker-compose up -d
sleep 20
docker exec coordinator psql -U citus -d citus -c "SELECT citus_add_node('worker1', 5432);"
docker exec coordinator psql -U citus -d citus -c "SELECT citus_add_node('worker2', 5432);"
docker exec coordinator psql -U citus -d citus -c "CREATE TABLE orders (id serial, tenant_id int, product_id int, quantity int, PRIMARY KEY(id, tenant_id));"
docker exec coordinator psql -U citus -d citus -c "SELECT create_distributed_table('orders', 'tenant_id');"
"""

vpc = aws.ec2.Vpc("citus-vpc", cidr_block="10.0.0.0/16", enable_dns_hostnames=True, enable_dns_support=True)
igw = aws.ec2.InternetGateway("citus-igw", vpc_id=vpc.id)
subnet = aws.ec2.Subnet("citus-subnet", vpc_id=vpc.id, cidr_block="10.0.1.0/24", map_public_ip_on_launch=True)
rt = aws.ec2.RouteTable("citus-rt", vpc_id=vpc.id, routes=[aws.ec2.RouteTableRouteArgs(cidr_block="0.0.0.0/0", gateway_id=igw.id)])
rt_assoc = aws.ec2.RouteTableAssociation("citus-rt-assoc", subnet_id=subnet.id, route_table_id=rt.id)

sg = aws.ec2.SecurityGroup("citus-sg",
    vpc_id=vpc.id,
    ingress=[
        {"protocol": "tcp", "from_port": 22, "to_port": 22, "cidr_blocks": ["0.0.0.0/0"]},
        {"protocol": "tcp", "from_port": 5432, "to_port": 5432, "cidr_blocks": ["0.0.0.0/0"]}
    ],
    egress=[{"protocol": "-1", "from_port": 0, "to_port": 0, "cidr_blocks": ["0.0.0.0/0"]}]
)

citus_instance = aws.ec2.Instance("citus-instance",
    instance_type="t2.medium",
    vpc_security_group_ids=[sg.id],
    ami="ami-04b70fa74e45c3917",
    subnet_id=subnet.id,
    key_name="CitusKeyPair",
    user_data=user_data,
    user_data_replace_on_change=True,
    opts=pulumi.ResourceOptions(depends_on=[rt_assoc])
)

pulumi.export("coordinator_ip", citus_instance.public_ip)
```

Run the deployment and save the outputted IP:

```bash

```

## Step 4: Implement the Benchmark and Analysis Script

Create a file named `citus-benchmark-lab/app/benchmark.py` with the following contents:

```python
import os
import time
import concurrent.futures
from sqlalchemy import create_engine, text

COORDINATOR_IP = os.environ.get("COORDINATOR_IP", "127.0.0.1")
DB_URI = f'postgresql://citus:citus_password@{COORDINATOR_IP}:5432/citus'
engine = create_engine(DB_URI)

def run_explain():
    with engine.connect() as conn:
        print("\n--- Query Plan: Single Tenant (Routed) ---")
        result = conn.execute(text("EXPLAIN SELECT * FROM orders WHERE tenant_id = 501;"))
        for row in result:
            print(row[0])
        
        print("\n--- Query Plan: All Tenants (Scatter-Gather) ---")
        result = conn.execute(text("EXPLAIN SELECT count(*) FROM orders;"))
        for row in result:
            print(row[0])

def insert_order(tenant_id):
    with engine.connect() as conn:
        conn.execute(
            text("INSERT INTO orders (tenant_id, product_id, quantity) VALUES (:t, 1, 1)"),
            {"t": tenant_id}
        )
        conn.commit()

def benchmark_inserts():
    start_time = time.time()
    total_inserts = 1000
    
    print(f"\nStarting benchmark: Inserting {total_inserts} records concurrently...")
    with concurrent.futures.ThreadPoolExecutor(max_workers=20) as executor:
        futures = [executor.submit(insert_order, i % 10) for i in range(total_inserts)]
        concurrent.futures.wait(futures)
        
    duration = time.time() - start_time
    print(f"Finished. Inserted {total_inserts} records in {duration:.2f} seconds.")
    print(f"Throughput: {total_inserts / duration:.2f} inserts/sec\n")

if __name__ == '__main__':
    run_explain()
    benchmark_inserts()
```

**Explanation:**
- `conn.execute(text("EXPLAIN ..."))`: Executes raw SQL to fetch the PostgreSQL query plan. The first query is highly optimized for a single tenant, while the second triggers a scatter-gather operation.
- `concurrent.futures.ThreadPoolExecutor`: Spawns multiple threads to simulate concurrent clients hitting the database simultaneously.
- `insert_order(tenant_id)`: Inserts a simple record. The `i % 10` logic ensures data is distributed across 10 different simulated tenants, distributing the write load across the Citus shards.
